dal-c

A small library of reusable C components built to a Design Assurance Level C style — requirements-driven, MC/DC-covered, statically analysed, no dynamic memory.

Each component is a self-contained C99 module with an explicit set of high- and low-level requirements, requirements-based tests, and structural coverage (statement, branch, and Modified Condition/Decision Coverage). The build runs with -Wall -Wextra -Wpedantic -Werror -Wconversion and a few more; the CI pipeline fails on any warning, any uncovered line or condition, any static-analysis finding, or any break in the requirements trace.

How each component is built

  1. Requirements — requirements/<module>.md: high-level requirements, then low-level requirements that each trace up to one or more HLRs and name the function that implements them.
  2. Code — every implementation block carries an /* LLR-... */ tag, giving a bidirectional trace between requirement and source.
  3. Requirements-based tests — tests/test_<module>.c: each test names the requirement it verifies; compound decisions get cases chosen for MC/DC.
  4. Structural coverage — make coverage instruments with GCC condition coverage; CI fails under 100% line and 100% branch/condition.
  5. Traceability — tools/gen_rtm.py rebuilds the matrix and fails the build on any orphan requirement, missing implementation, or missing test.
  6. Static analysis — cppcheck on every push; MISRA C:2012 is the coding-style target, with deviations documented in include/sc_common.h.
